    Mathematical Core

    The statistical foundations driving the inference engine.

    Principal Component Analysis (PCA)
    Z = XW

    Used to anonymize and reduce dimensionality of transaction features. X is the original data matrix, W is the matrix of principal components.

    Correlation Coefficient
    r = ∑[(xi - μx)(yi - μy)] / [n∙σx∙σy]

    Measures linear relationship between two variables. μ is the mean and σ is the standard deviation.

    Confusion Matrix & Metrics
    Precision = TP / (TP + FP)
    Recall = TP / (TP + FN)
    F1 = 2 ∙ (P ∙ R) / (P + R)

    Key metrics for binary classification (fraud/non-fraud).

    ROC Curve & AUC
    TPR = TP / (TP + FN)
    FPR = FP / (FP + TN)

    The ROC curve plots True Positive Rate vs. False Positive Rate. AUC quantifies overall model performance.

    Anomaly Detection
    z = (x - μ) / σ

    Statistical thresholds (Z-Score). Transactions with high |z| scores may be flagged as anomalies.

    Execution Workflow

    01
    📊
    Data Ingestion & Prep
    Raw transaction data is ingested and normalized. We apply Z-score scaling x' = (x - μ) / σ to ensure all features contribute equally. A safety layer auto-fills missing technical data with statistical averages, ensuring the system never crashes.
    02
    🧠
    Feature Engineering
    Extracting human-centric behavioral patterns. We analyze time-delta, location consistency, and spending velocity to create a behavioral signature.
    03
    📉
    Dimensionality Reduction
    Principal Component Analysis (PCA) transforms high-dimensional data into 28 orthogonal vectors (V1-V28), preserving privacy while retaining 95% variance. Think of it like a blender: raw features (Location, Age, Device) are mixed into a "smoothie" (V1, V2, etc.). You can't see the individual ingredients, but the mathematical "flavor" remains.
    04
    🤖
    Hybrid Model Training
    A dual-engine approach: XGBoost for supervised classification of known fraud patterns, and Isolation Forest for unsupervised anomaly detection.
    05
    ⚡
    Real-Time Inference
    The trained model serves predictions in milliseconds via API. SHAP values are calculated instantly to provide explainability for every decision.

    Interpreting Key Features

    V14
    Why V14 = -16.0?
    Think of the 'V' features like room temperature. For most legitimate transactions, V14 is close to 0. A value of -16.0 is a statistical outlier—16 standard deviations from the norm. It’s like the temperature suddenly dropping to -50°C. In this dataset, such extreme negative values are almost exclusively found in fraud cases.
    Time
    Why Time = 400?
    'Time' is the number of seconds since the dataset recording started. A low value like 400 means the transaction happened very early. Fraudsters often use bots to run thousands of transactions quickly. A low time value can simulate a transaction happening in a "cluster" of suspicious activity.
    V4
    Why V4 = 9.0?
    Unlike V14, our analysis shows that for V4, higher is worse. A normal V4 is around 0, while high positive numbers (like +9.0) are linked to fraud. A thief's "fingerprint" is often a combination of these extremes: (V14 is very low) + (V4 is very high).

    PCA Conversion Logic
    How Human-Centric Features Are Converted to PCA Vectors in Credit Card Fraud Detection

    Introduction

    In real-world credit card fraud detection systems, raw transaction data contains human-readable features such as Transaction Amount, Time, Merchant ID, IP Address, Device Type, Location, and Frequency of Transactions. However, public fraud datasets often show anonymized features like V1, V2, V3 … V28.

    These are Principal Components created using Principal Component Analysis (PCA) to:

    • ✅ Protect user privacy
    • ✅ Reduce correlated features
    • ✅ Improve model efficiency
    • ✅ Compress many features into fewer meaningful components

    Full Conversion Pipeline

    How Each Type Converts

    🔢
    Numeric Features
    Examples: Amount = ₹5000, Frequency = 8, Credit Limit = ₹1,00,000
    Standardization Process:
    Z = (X - Mean) / StdDev
    Example:
    Amount = 5000, Mean = 3000, Std = 1000
    Z = (5000 - 3000) / 1000 = 2
    ⏱️
    Timestamp Features
    Time-based data must be converted into cyclical numeric logic.
    Raw Input:
    2026-04-22 02:30 AM
    Converted into:
    Hour = 2
    Day = Monday = 1
    Weekend Flag = 0
    (These values are then scaled)
    🔠
    String & Boolean
    Frequency Encoding (e.g. Merchants):
    Amazon (1500 txns) → 1500
    One-Hot Encoding (e.g. Currency):
    INR → [1, 0, 0]
    USD → [0, 1, 0]
    Boolean (True/False):
    New Merchant Flag = True → 1

    The PCA Matrix Transformation

    After conversion, the raw data becomes a complete numeric matrix X. PCA then finds the hidden patterns using the weights matrix W.

    V = X · W

    Example Output Generation:

    Suppose: V1 = 0.5(Amount) + 0.3(Hour) + 0.6(Frequency) + 0.2(Risk)

    V1 = 0.5(2.0) + 0.3(-1.5) + 0.6(0.8) + 0.2(0.7)
    V1 = 1 - 0.45 + 0.48 + 0.14 = 1.17

    The final dataset stores V1 = 1.17 instead of the raw user data, providing mathematically complete but privacy-secured records for the AI to train on.
